# 冲突解析模块

`conflicts` 只读代码和索引，在 Git 私有目录 `git-helper-backups/<唯一编号>/` 保存 HEAD、索引冲突条目、工作区原始字节和 stage 1/2/3 blob，不修改代码或暂存。快照可能含敏感信息，不能上传；它仅覆盖冲突路径，不是完整仓库备份。

## 展示与选择

逐文件展示完整冲突代码、base、ours、theirs，说明 base 是共同祖先。普通 merge 的 ours 为当前分支，theirs 为待合并分支；rebase 的 ours 通常为重放目标，theirs 为被重放提交，必须先确认上下文。

提供选项，并展示每个方案拟写入的具体代码及可能丢失的逻辑：

1. 保留当前侧，说明舍弃的传入改动。
2. 保留传入侧，说明舍弃的当前改动。
3. 人工组合，展示完整候选并解释接口兼容性和重复逻辑。
4. 暂不处理，保留现场。

二进制只显示长度与 blob ID，不解码后写回；删除/修改、重命名、符号链接、子模块冲突需逐路径拟定方案，不能套用文本拼接。

## 用户选定后

1. 重新核对 HEAD、索引 stage/blob、工作区原始字节与快照一致。有变化则重新展示和选择，不能沿用过期决策。
2. 保留快照，只对选定路径写入选定代码；检查实际 diff 与候选一致。删除前备份原始文件，不批量 checkout --ours/--theirs。
3. 检查剩余标记、`git diff --check` 和项目相关测试。成功后 `git add -- <明确路径>`；删除必须用户明确选择后 `git rm -- <路径>`。
4. `git ls-files -u` 确认剩余冲突，审阅暂存 diff。测试失败停止；继续 merge/rebase、提交或推送仍须在用户原任务授权内。

禁止 `reset --hard`、`clean -fd`、强推、自动丢弃工作区。取消 merge/rebase 前，备份操作后新增修改、索引和未跟踪文件，解释 abort 影响并按用户选择执行。
